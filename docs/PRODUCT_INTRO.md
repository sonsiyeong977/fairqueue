## 한 줄 소개

> 저희는 유저가 남보다 빨리 사도록 돕는 매크로가 아니라, **플랫폼이 결제 실패 없이, 매크로 없이, 분쟁 없이 티켓을 판매하도록 돕는 결제 보증 레이어**입니다.

---

## 1. 타깃

### 1차 타깃 — 티켓팅 플랫폼 운영사
- 콘서트, 스포츠, 팬미팅 등 고수요 예매를 운영하는 플랫폼
- 결제 실패로 인한 매출 손실, 매크로 대응 비용, 환불 처리 CS 부담을 안고 있는 사업자

### 2차 타깃 — 최종 구매자(팬)
- 대기열에서 순번을 기다리다 결제 실패로 좌석을 놓친 경험이 있는 유저
- 매진 시 환불이 지연되어 불편을 겪은 유저

---

## 2. 문제

기존 티켓팅 시스템은 세 가지 구조적 문제를 안고 있습니다.

| 문제 | 설명 | 영향 |
|---|---|---|
| 결제 실패 | 대기열 순번이 왔을 때 카드 정보 입력 지연·오류로 결제 자체가 실패 | 플랫폼의 순수 매출 손실 |
| 환불 지연 | 매진 확정 후 환불까지 PG 정산 주기상 며칠 소요 | CS 부담, 고객 불만 |
| 매크로/암표 | 비공식 자동화 도구의 대기열 우회 시도 | 지속적인 탐지·차단 비용 |

이 세 문제는 서로 연결되어 있습니다. 결제가 실패할 수 있다는 불확실성이 크기 때문에 유저들은 더 빠른 수단(매크로)에 의존하게 되고, 플랫폼은 이를 막기 위해 더 많은 비용을 씁니다.

---

## 3. 솔루션

FairQueue는 유저가 조건과 함께 결제 금액을 **온체인 에스크로에 미리 예치**하게 합니다.

1. 유저가 자연어로 조건(이벤트, 좌석 등급, 최대 가격, 대안 조건)을 입력
2. Gemini가 이를 구조화된 조건(`primary` + `fallback_rules`)으로 변환
3. 예상 최대 결제 금액을 Solana 온체인 에스크로에 사전 예치
4. 정상적인 대기열 순서를 그대로 준수 (1계정 1에이전트, 우회 없음)
5. 실제 판매 가능 좌석과 조건을 비교해 Gemini가 3단계로 자동 판단
   - 1차 희망 조건 충족 → 즉시 결제
   - 1차 매진, 대안 조건 충족 → 대안으로 즉시 결제
   - 모두 매진 → 즉시 전액 환불
6. 결제 시 실결제 금액과 예치 금액의 차액은 자동으로 유저에게 반환

이 구조에서 결제 실패는 원천적으로 발생하지 않습니다. 자금이 이미 온체인에 확보되어 있기 때문입니다. 환불도 PG 정산을 기다릴 필요 없이 즉시 처리됩니다.

### 기존 매크로와의 차별점

| | 기존 매크로 | FairQueue |
|---|---|---|
| 대기열 처리 | 우회·편법 시도 | 정상 순서 그대로 준수 |
| 목적 | 남보다 빨리 선점 | 결제 실패 방지 + 즉시 투명 환불 |
| 플랫폼과의 관계 | 대립적 (탐지·차단 대상) | 협력적 (매출 손실 방지 인프라) |

---

## 4. 왜 Solana × Google Cloud인가

**Solana**
- 에스크로 예치/해제가 즉시, 저비용이라 소액도 부담 없이 예치 가능
- 매진 확정 즉시 온체인 자동 환불 — 기존 카드망은 정산 주기상 며칠 소요
- 전 과정이 온체인에 기록되어 배정 공정성 분쟁 시 검증 가능

**Google Cloud / Gemini**
- 자연어 조건 파싱: 유저의 요청을 1차 조건과 대안 규칙으로 구조화
- 다단계 판단: 실제 좌석 데이터를 근거로 1차 → 대안 → 환불을 순서대로 판단하며, 판단마다 근거(reasoning)를 함께 생성

|---|---|

| 매출 손실 방지 가치 공유 | 결제 실패로 인한 손실 감소분의 일부를 플랫폼과 공유하는 성과 기반 모델 (확장 옵션) |

## 6. 검증된 구현 (No Mock-up)

아래는 실제 Solana Devnet 트랜잭션과 실제 Gemini API 호출로 end-to-end 검증된 내용입니다.

| 단계 | 검증 내용 |
|---|---|
| 자연어 → 조건 파싱 | Gemini가 유저 요청을 구조화된 조건으로 변환 |
| 플랫폼 API 연동 | Express 기반 좌석 상태 API와 실시간 HTTP 통신 |
| 온체인 에스크로 예치 | Agent keypair의 사람 개입 없는 자율 서명으로 Devnet 트랜잭션 발생 |
| 3단계 자동 판단 | 1차 조건 성공 / 대안 조건으로 성공 / 전량 매진 후 환불, 세 시나리오 모두 검증 |
| 조건별 에스크로 해제 | 결제 시 판매자 지갑, 환불 시 유저 지갑으로 정확히 분기 |
| 거스름돈 자동 반환 | 예치 금액과 실결제 금액의 차액을 자동으로 유저에게 반환 |

---

## 7. 아키텍처

```
User (자연어 조건 입력)
   ↓
Gemini — 조건 파싱 (primary + fallback_rules)
   ↓
Solana On-chain Escrow — 예상 최대 금액 예치 (자율 서명)
   ↓
Platform Simulator API — 실제 좌석 상태 조회
   ↓
Gemini — 1차 → 대안 → 환불 다단계 판단
   ↓
   ├─ SETTLE (판매자 지갑으로 결제, 차액 자동 환불)
   └─ REFUND (유저 지갑으로 전액 환불)
   ↓
Solana Explorer — 모든 트랜잭션 검증 가능
```

## 8. 확장 가능성

- **부정 탐지 레이어**: 요청 로그 패턴 분석을 통한 다중 계정 매크로 탐지
- **온체인 프로그램화**: 현재는 백엔드가 관리하는 커스터디얼 에스크로 방식이나, 향후 Anchor 기반 온체인 프로그램(PDA)으로 전환해 신뢰를 완전히 탈중앙화 가능
- **적용 범위 확장**: 티켓팅 외에도 한정판 커머스, 예약 시스템 등 "매진 가능성이 있는 선착순 거래" 전반에 적용 가능
